**What changed since the last round:** you asked for the PWA/Play Store app to feel faster and smoother. Two changes for that, on top of the original PWA files:
- `public/sw.js` — was "network-first" for everything; now serves your JS/CSS/image files instantly from cache when available (updating them in the background), so a repeat visitor doesn't wait on a network round-trip just to see the app shell. The actual page content (HTML) still always checks the network first, same as before, so you never see a stale page after a deploy — this only speeds up the surrounding app shell.
- `index.html` — added two `<link rel="preconnect">` tags for your backend API and Cloudinary (the image host). These start the connection handshake the moment the page begins loading instead of waiting for the first API call or image request — shaves a real round-trip off how quickly the app starts showing real content, especially on mobile data. Everything else in `index.html` (GA4 tag, manifest link, icons, meta tags) is untouched.

## STEP 3 — Test it

1. **Desktop Chrome/Edge**: open the live site. Look at the right side of the address bar for a small install icon (monitor with a down-arrow, or "+"). Click it → "Install" → the site opens in its own window with no address bar, showing your real logo as the app icon.
2. **Android Chrome**: open the site on a phone, tap ⋮ → "Add to Home Screen" / "Install app". Confirm the home-screen icon is your logo, and tapping it opens full-screen with no browser bar.
3. **iPhone Safari**: open the site, tap the Share icon → "Add to Home Screen". Confirm the icon and name look right.
4. **Speed check**: close the installed app fully, reopen it — after the first open, it should feel noticeably snappier on the second and later opens (the shell is now served from cache instantly while it refreshes in the background).
5. **Offline check (optional)**: after installing and opening once while online, turn on Airplane Mode and reopen — the page shell should still load (live data like the exam list will correctly show a network error until you're back online — that's intentional).
6. **Lighthouse check (optional, technical)**: Chrome DevTools → Lighthouse → run a "Progressive Web App" audit. Should now pass the installability checks.

## What's next — Google Play Store (Stage 4)

Once this is confirmed working, the remaining step for the Play Store is a **Trusted Web Activity (TWA)** — a thin Android wrapper around this same live website, generated by a free tool (PWABuilder.com — paste in your site's URL and it packages it). It will pick up this same logo as the app icon automatically, since it reads it straight from your manifest. That tool will also ask you to add one more small verification file to the site (`/.well-known/assetlinks.json`) proving you own both the site and the app — that file's exact content doesn't exist until you've run PWABuilder and have the Android package's signing fingerprint, so it comes after that step. After that: create the Play Console listing (name, screenshots, description, privacy policy), pay the one-time ~$25 (~₹2,000) fee, upload, and submit for review.

**On your "ensure changes show up in PWA and Play Store app" question:** because this is a TWA and not a separately-coded native app, the Play Store app and the website stay the *same running app*. Every future feature or fix deploys the normal way (GitHub → Vercel redeploy) and shows up in both the installed PWA and the Play Store app automatically, the next time someone opens it. No separate Play Store update or re-submission is ever needed for ordinary changes. The only time you'd need to touch the Play Store listing again is something structural and rare — changing the app's package name, or moving to a different domain.
